# Golinks: plan

A local, policy-safe "smart bookmarks" service for macOS. Everything runs from this
folder using tools already on the machine (Node 20, Chrome, Apple Shortcuts, launchd).
No new applications, no compiled binaries, no npm packages with native code, no AI.

## Constraints that shape every decision

- Company policy flags any installed application or self-compiled binary. Nothing here
  produces a `.app`, a Mach-O binary, or a Chrome extension.
- Runtime is the already-present Node 20 (nvm). The service has zero npm dependencies.
- Menu bar presence comes from Apple Shortcuts pinned to the menu bar, not a native app.
- Most work URLs sit behind SSO. Any page-derived data (title, snapshot) for those pages
  must be captured in the user's browser at add time, not fetched by the server.
- Data must be plain files that can live in git and be edited by hand.

## Shape of the outcome

```
go-links/
  PLAN.md
  server.js              Node HTTP service, no dependencies, port 7777
  lib/                   search, ranking, rules, import, snapshots, store
  public/index.html      single-page web UI (vanilla JS, no build step)
  public/app.js
  public/style.css
  data/links.json        the link store (git tracked)
  data/rules.json        domain and path tagging rules (git tracked)
  data/templates.json    parameterized links and go-link keywords (git tracked)
  snapshots/<id>.jpg     page thumbnails, ~480px wide (git tracked, small)
  logs/                  launchd stdout/stderr (git ignored)
  bin/golinks           control script: install|uninstall|start|stop|restart|status|logs
  bin/node               symlink to the current nvm node, regenerated by golinks install
  launchd/dev.golinks.plist.tmpl   plist template, rendered by golinks install
  shortcuts/             exported .shortcut files plus setup notes
  bookmarklet/           the "Golinks" bookmarklet source
```

Outside the folder, exactly one file: `~/Library/LaunchAgents/dev.golinks.plist`.

## Lifecycle

- `bin/golinks install` renders the plist with absolute paths, creates `bin/node`
  symlink, bootstraps the agent. Service starts now and at every login.
- `stop` runs `launchctl bootout`; `start` runs `bootstrap`; `restart` runs
  `kickstart -k`; `status` shows pid, port, link count, last exit code.
- KeepAlive uses `SuccessfulExit=false`: crashes restart within seconds, a clean exit
  (code 0) stays down. `POST /quit` calls `process.exit(0)` so the web UI and the
  Shortcut can stop the service.
- Service watches `data/*.json` and hot-reloads, so `git pull` needs no restart.
- `uninstall` removes the plist and agent. The folder and data are untouched.

## Data model

`data/links.json` is an array of records with stable ids:

```json
{
  "id": "k7f2q9",
  "url": "https://example.atlassian.net/wiki/spaces/EP/pages/123/Design",
  "title": "Event Portal design notes",
  "description": "",
  "tags": ["confluence", "event-portal"],
  "aliases": ["ep design"],
  "keyword": "epdesign",
  "notes": "",
  "collection": null,
  "created": "2026-09-08T10:00:00Z",
  "lastUsed": "2026-09-08T10:00:00Z",
  "useCount": 0,
  "snapshot": "snapshots/k7f2q9.jpg",
  "snapshotAt": "2026-09-08T10:00:00Z",
  "source": "shortcut"
}
```

- `keyword` is the go-link short name (`go epdesign`). Unique when set.
- `data/templates.json` holds parameterized links:
  `{ "jira": "https://example.atlassian.net/browse/{0}", "conf": "https://.../search?text={q}" }`
- `data/rules.json` holds tagging rules: `{ "match": "atlassian.net/wiki", "tags": ["confluence"] }`
  and path patterns such as `{ "match": "/browse/([A-Z]+)-\\d+", "tags": ["jira", "$1"] }`.
- Writes are atomic (write temp file, rename). A `.bak` of the previous version is kept.

## HTTP API (localhost only)

```
GET  /                      web UI
GET  /api/links             all links (optionally ?q= ?tag= ?collection=)
GET  /api/search?q=         ranked results with match highlights
GET  /go/:text              omnibox entry point: keyword, template, or best match; 302 redirect
GET  /open/:id              records use, 302 to url
POST /api/links             add (url, title?, description?, tags?, snapshot? base64)
PUT  /api/links/:id         edit
DELETE /api/links/:id
POST /api/links/:id/snapshot   replace snapshot (base64 jpeg)
POST /api/enrich            given a url, return suggested title, tags, og image (server fetch, public pages)
POST /api/import/chrome     import from a Chrome or Brave Bookmarks file
POST /api/import/text       extract URLs from pasted text
GET  /api/health
POST /quit
```

The server binds 127.0.0.1 only and rejects non-local origins.

## Search and ranking

- Tokenized fuzzy match over title, url, tags, aliases, notes, keyword.
- Abbreviation match: `ep` matches "Event Portal" by initials.
- Operators: `tag:x`, `site:x`, `col:x`, `unused:90d`, `added:7d`.
- Score = text match quality x frecency, where frecency decays over roughly 30 days and
  weights useCount. Exact keyword match always wins.
- `/go/` resolution order: exact keyword, template prefix (`jira 1234`), then top search hit.
  If no confident hit, redirect to the web UI with the query prefilled.

## Capture paths

1. Menu bar Shortcut "Add current tab": AppleScript gets Chrome's active tab url and
   title; Take Screenshot of the Chrome window, crop tab strip, resize to 480px, JPEG;
   ask for tags with suggestions fetched from `/api/enrich`; POST to `/api/links`.
2. Bookmarklet: sends url, title, meta description, selected text, og:image url to
   `/api/links` via a small popup page served by the service. Fallback if Chrome
   automation permission is blocked. No snapshot.
3. Web UI paste box: server-side enrich (title, og image, headless Chrome thumbnail for
   public pages, generated tile otherwise).
4. `POST /api/links` for scripts and Claude Code.

## Snapshots

- Primary: Shortcut window screenshot at capture time (works for SSO pages).
- Fallback for public pages: og:image, else headless Chrome
  (`Google Chrome --headless --screenshot --window-size=1280,800 --user-data-dir=<tmp>`),
  with login-page detection to avoid saving sign-in screens.
- Final fallback: generated SVG tile with favicon and domain colour.
- Per-link "refresh snapshot" action. Staleness hint after 90 days (configurable).
- Optional "snapshot on revisit" in the open Shortcut, off by default.

## Menu bar and hotkeys (Shortcuts)

- "Links: search" pinned to menu bar, hotkey Ctrl+Option+L. Ask for input, GET
  `/api/search`, Choose from list, open. If service is down, offer to start it.
- "Links: add current tab" as above, hotkey Ctrl+Option+A.
- "Links: stop service" and "Links: start service" as menu entries.
- Chrome site search keyword `go` pointing at `http://localhost:7777/go/%s`.

## Web UI

- Command palette layout: search box at top, results as list or card grid, arrow keys
  to move, Enter opens, Cmd+Enter copies URL, Cmd+K focuses search.
- Card grid shows snapshot, title, tags, last used. Hover preview in list mode.
- Edit drawer per link: title, tags (chips with suggestions), aliases, keyword, notes,
  collection, snapshot refresh.
- Views: All, Recent, Most used, Untagged, Stale, per tag, per collection.
- Import page: Chrome and Brave bookmark files, pasted text. Preview before commit.
- Settings: port, snapshot staleness, templates and rules editors, service stop.
- Dark and light theme following the system.

## Milestones

M0  Permission gates (first hour). Build the two Shortcuts in skeleton form and test:
    (a) AppleScript read of Chrome active tab, (b) window screenshot. Record which
    permissions were granted or blocked by Jamf. Decide snapshot strategy accordingly.

M1  Service core. server.js, store with atomic writes and hot reload, search and
    ranking, /go resolution, templates and rules, health and quit endpoints.
    golinks with install/uninstall/start/stop/restart/status/logs. Plist template.
    Verify start at login and self-quit behaviour.

M2  Web UI v1. Search, list and card views, open and copy, edit drawer, tag chips,
    views by tag and recency. Keyboard navigation.

M3  Capture. Shortcuts "search" and "add current tab" with snapshot, bookmarklet,
    /api/enrich with rules-based tagging, server-side og image and headless thumbnail,
    generated tile fallback. Chrome `go` keyword documented in shortcuts/README.

M4  Import and hygiene. Chrome and Brave bookmark import with preview, text import,
    URL normalization, duplicate detection, stale view, snapshot refresh.

M5  Polish. Collections with open-all, settings page, dark mode, README with setup
    steps, git ignore for logs, backup rotation.

Each milestone ends with the service running under launchd and used for real.

## Explicitly out of scope for v1

AI tagging or summaries, Chrome extension, clipboard watching, calendar integration,
full-text indexing of page content, browser history mining, multi-user access.

## Known limitations accepted

- Shortcuts palette is type, Enter, pick, not live filtering. Omnibox `go` is the
  fast path.
- Menu bar shows a single Shortcuts entry, no rich dropdown.
- Server cannot snapshot SSO pages on its own.
- Shortcuts hotkeys may need re-enabling after macOS updates.
